Business record matching

Same business.
Different records.

A practical entity resolution system that links records across three sources, even when business names and addresses are written differently.

What the model does

It narrows millions of possible pairs to a short candidate list, compares useful name and address signals, then ranks likely matches with a trained model.

How a match is made

01 · CLEAN

Normalize records

Standardize names, common address forms, numbers, and selected transliterations.

02 · FIND

Retrieve candidates

Search within the same country using weighted name and address keys.

03 · COMPARE

Build pair signals

Measure name, address, number, and relative-rank similarities.

04 · DECIDE

Rank with LightGBM

Score each pair and keep a match only when it clears the tuned threshold.

What was improved

  • Prepared training one country at a time to reduce peak memory use.
  • Compared retrieval widths of 20, 40, 60, and 80 using the same holdout.
  • Selected retrieval 80 and an eight-candidate scoring shortlist from measured validation results.
  • Reworked prediction output to group links in small disk-backed shards.

Reproducibility and limits

The holdout used Iowa and Rajasthan records from the supplied training labels. The threshold was chosen on that holdout, so results may be optimistic and may differ in other regions.

Not a test score: test labels were not supplied. The reported metric is a training-data validation estimate, not a leaderboard result.

Challenge records and prediction files are excluded from the repository. The pipeline runs locally with the challenge data supplied by the user.
